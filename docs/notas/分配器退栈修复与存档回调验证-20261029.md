## R18–R20：profile 读取越界写坏块头的功能修复

- R18 捕获真实 61015 分配失败内层：`H=842028A4 / VT=8210A858 / T=82C34428`，首次 search 返回 0，resolver 返回 824B0630，最终失败检查返回 0，进入 82C345F8。不是 wrapper 自行拒绝。
- R19 硬件 watch 捕获块头字段首次变零的写者：`ByteStream::Write → BinarySetting::Append → XamUserReadProfileSettingsEx → sub_82E82E70 → sub_8242C808 → sub_8232EE98 → sub_8232F6B8`。watch 触发前，同一次 memcpy 已部分覆盖该字段；这是首次变零的证据，不能声称精确捕获 CPU 第一个越界字节。
- 已有 profile 63E83FFF 的 payload 为 1024 字节，setting ID 编码容量为 1000；原 query 给出 header 48 + 1000 = 1048，实际 Append 写入 1024，越界 24 字节，恰覆盖相邻空闲块头的前 6 个 word。随后空块头仍被 unlink/记账并清除搜索状态，导致后续分配失败。
- 功能修复位于 [xam_user.cpp](<C:/Users/26095/cola/coding-cola/project-20261028-112651-101fe126/rex/nfsmw-nx-main/sdk/src/kernel/xam/xam_user.cpp>)：BINARY required 取 encoded 与实际已加载 payload 长度的较大值，query/read 共用计算，64 位累加并检查 32 位容量上限。不截断、不清档、不强塞 engine/ACK。
- R20 用 R15 的既有隔离存档重开，原失败阶段的 61015 请求返回 AF5DCCD0，并有真实 type9 全链。比赛验收、原 R17 停帧是否同源仍未完成；R20 黑屏时仍提交纯黑帧，不能把不同黑屏现象混为一种。
