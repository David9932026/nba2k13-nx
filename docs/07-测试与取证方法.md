# 07 · 测试与取证方法

这个项目里，**错误结论比没结论更贵**。所以证据形式固定成几种，别的形式不采信。

---

## 1. 铁律：视觉判断不算证据

不管是自己看图，还是让视觉模型看图，都只能用来**提出假设**。定案必须落在这几种数据上：

| 证据类型 | 怎么取 |
|---|---|
| 像素统计 | 解码 PNG，统计非零像素数、通道均值、边缘梯度 |
| 日志计数 | 某个标记行的条数、某个字段的数值变化 |
| 结构比对 | 两张图同一像素位置的差、集合运算（A∩B、A−B） |
| MD5 | 卡上文件与本地文件是否一致 |

被这条铁律救过的例子在最后。

---

## 2. 每次真机排查的标准流程

1. **确认跑的是哪个包**：日志里搜 `C11 BANNER build`，对时间戳。
   （有过一次整轮白测：分析的是旧包的行为，因为不知道卡上是哪个版本。）
2. **拉日志**：SD 挂载后整目录拷出，别只看最新一卷 —— 冻死的证据常在被切掉的那卷末尾。
3. **先看有没有硬错**：`Heap exhausted`、`DEVICE_LOST`、`C43 anillo estancado`、`rex_crash.log`。
4. **再看对应补丁有没有触发**：比如查 C47 的问题就先数 `[nativo] C47` 的条数。
   条数是 0 就说明这刀没打中，别继续沿着它分析。
5. **最后才看画面**，而且是用导出 PNG 做像素统计。

## 3. PNG 导出与统计

渲染器能把指定的渲染目标/解析图导出成 PNG（`volcar_destino_ancho` / `volcar_resuelta_ancho`）。
**只用于排查，平时必须设 0** —— 每秒几十次全管线同步，帧数会直接崩。

导出后不要用眼睛看，用 `tools/chequea_png.py` 解码（PNG unfilter + 逐通道统计）：

```bash
python3 tools/chequea_png.py <png>            # 宽高、通道、非零像素、通道均值
python3 tools/suelo_tot.py capturas_xxx       # 一整段里"黑像素占比 ≥15%"的帧数
python3 tools/abdiff.py  dir_a dir_b          # 两轮逐像素差异百分比
python3 tools/borde48.py capturas_xxx         # 接缝检测（见 §5）
```

典型判据：

| 场景 | 判据 |
|---|---|
| 头像框里是否叠了人 | 非零像素数对比 + 集合运算（`修前 − 干净的那张` = 多出来的像素） |
| 地板是否发黑 | 画面下 2/3 的"近黑像素占比"，跨整段聚合 |
| 两层画面/接缝 | x=639\|640、y=359\|360 处的梯度与参考梯度比 |

## 4. A/B 的坑：演示模式每次不一样

PC 上用 `input-menu.txt` 跑演示模式，**每次随机球队和场馆**。两轮之间逐像素差异 **50–80%**，
根本不是同一帧 —— 拿"同一时刻的截图"做对比是错的。

正确做法：

- 跨整段**聚合统计**（比如"这段 245 秒里，黑地板帧 10 张 vs 25 张"）
- 或者用能复现固定路径的脚本（`input-pause.txt` 之类），并且**先确认两轮的 `[FRAMESIG]` 一致**
- 或者关掉变量只留一个（一次只改一个 cvar）

## 5. 接缝检测（`borde48.py`）

两层/拼接错误的典型形态：某个象限突然变成一块模糊或去饱和的矩形。
与其问"看起来是不是两个画面"，不如量**边界梯度**：

```
参考梯度 ref = 画面自身的平均邻像素差
接缝判据     = 边界处梯度 > 3 × ref + 6
```

一轮 60 帧里 `frames_with_seam` 的个数就是指标。C48 就是靠它判定的（修前 10 张、修后 2 张）。

## 6. 崩溃/冻死栈的符号化

- 构建产物里的符号表：`out/build/sw/nba2k13` + `nm-final.txt`（**87,107 个符号**）
- 脚本：`tools/simboliza-freeze.py`（冻死现场）、`tools/simb2.py`（通用）
- 常查的几个地址：

| 地址 | 符号 |
|---|---|
| `0x3ec7548` | `binderCreate + 0x18`（冻死时全线程的落点） |
| `0x3ec3688` | `svcWaitProcessWideKeyAtomic` |

读到 `binderCreate+0x18` 基本就可以判定是"整机卡死"而不是游戏逻辑错 —— 那个位置是 nv 服务 IPC 堵住了。

## 7. 上卡后的铁验证

```powershell
$a = (Get-FileHash .\nba2k13.nro -Algorithm MD5).Hash
$b = (Get-FileHash F:\switch\nba2k13\nba2k13.nro -Algorithm MD5).Hash
```

不一致就是没推成功（MTP 下尤其常见），别让人白测一轮。

## 8. 三个"差点信了"的假象

### 8.1 导出的 PNG 全黑

看着像"渲染目标里没内容"。实际是 `EscribirPngDeImagen` 用 **COLOR aspect** 去拷 **DEPTH 图** = 无效拷贝，
导出来当然全零。用 `chequea_png.py` 做字节级验证才发现（修法 = C41a）。

### 8.2 "GPU 被锁死了"

用户看到 GPU 利用率 0、CPU 100%，判断是 GPU 被锁。实际是 PM4 环死锁后**没有命令喂进去**，
CPU 在环上原地空转（33 万圈/秒）。判据是看环的读指针有没有前进（C43）。

### 8.3 "新包比以前差"

预热 MV 卡死，第一反应是"是不是新加的补丁弄坏了"。真相要靠**和上一个正常包的日志做差异比对**：
好那场是 `[PHYSPAD] 64MB-aligned request widened…`，坏的三场全是 `[PHYSPAD] C41b relleno desactivado`。
一眼定案，比猜十轮都快。

## 9. 真机测试的配合方式

有些东西只有人能提供：

| 需要人做的 | 为什么 |
|---|---|
| 电源键重启 / 插拔 SD | 自动化做不了 |
| 面板里切 cvar 做开/关对比 | PC 脚本走不到某些界面（技术统计页、MV 固定帧） |
| 游戏内拍照 | 游戏运行时系统截图被禁 |
| 描述"哪个半场、哪一版、超不超频" | 这类对照观察非常精确，是最好的一级证据 |

反过来，凡是能自动化的（编译、跑固定脚本、抓帧、算像素、比 MD5）都不要让人代劳。
