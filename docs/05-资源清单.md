# 05 · 资源清单

这一页列清：**什么要你自己准备**、**什么可以从哪拿**、**中间产物长什么样**。
本仓库不包含下面第 1、2 节里的任何文件。

---

## 1. 必须自备：游戏本体（版权作品）

| 项 | 值 |
|---|---|
| 游戏 | NBA 2K13，Xbox 360 版 |
| Title ID | `545408A2` |
| 主可执行体 | `default.xex`，**8,122,368 B** |
| 来源 | 你自己合法拥有的光盘 / 数字版，自行导出 |

这一份是整条链的输入：codegen 从 `default.xex` 生成 C++，解包工具从游戏包里取资产和着色器容器。
**没有它什么都做不了**，而且不能由任何人代传。

## 2. 由游戏本体派生的中间产物（同样不能分发）

这些都在你本机生成，用于对齐检查。大小写在这里，方便你确认自己那套是不是对上了。

| 产物 | 大小 / 数量 | 怎么来 |
|---|---|---|
| 解包后的资产树 | **16.02 GiB / 11,822 个文件**，CRC32 99.4% | 用 360 包解包工具从游戏包导出 |
| 原始游戏包（压缩） | ~8 GB | **不能直接用于扫着色器容器**，必须解包 |
| 重编译 C++ 代码 | **59,585 个函数 / 435 个文件**（~226 MB） | rexglue codegen 跑 `default.xex` |
| 着色器容器候选 | 84,078 个，去重后 **7,338 个**（910 VS / 6,428 PS） | 在解包树里按签名 `0x102A1100` 扫 |
| 着色器库 | `NBA2K13_shaders.nfsp`，**259,964,744 B**，**7,380 个** | `app/tools` 里的打包器（见 06） |
| 可执行 NRO | `nba2k13.nro`，约 **83–84 MB** | 构建产物 |
| 启动器 NSP | `012a13c0de5f1000.nsp`，约 330 KB | `hacbrewpack` 打包，只放一个入口，指向 `sdmc:/switch/nba2k13/nba2k13.nro` |

| 组件 | 用途 | 地址 / 说明 |
|---|---|---|
| **ReXGlue SDK** | Xbox 360 静态重编译运行时与工具链 | https://github.com/rexglue/rexglue-sdk |
| **nfsmw-nx** | Switch 原生 Vulkan 渲染器（本项目的渲染器来源，GPL-3.0） | https://github.com/StevensND/nfsmw-nx |

## 5. 需要研究的资料（干活时会反复查）

| 主题 | 为什么需要 |
|---|---|
| **PM4 包格式** | 环上每一包的 opcode 含义（`0x36` 绘制、`0x3c` WAIT_REG_MEM、`0x27` IM_LOAD…）。xenia 的 `xenos.h` 是最实用的表 |
| **Xenos 的 EDRAM / 瓦片** | 80×16 瓦片、2048 瓦片、tile resolve 的规则。决定"为什么游戏要 1600×1600 的阴影图" |
| **Xenos 纹理格式表** | 格式号 ↔ 实际布局（`6` = 8888、`22` = 24_8_F 深度、`59` 疑似 DXT5A、`37` = 8888_GAMMA…） |
| **fetch 常量布局** | 字 0 类型/符号位，字 1 基地址+格式，字 2 宽高 13 位，字 3 swizzle，字 5 尺寸信息 |
| **D3D9 → 360 的差异** | 尤其是 VS 的 fetch 会被 D3D 改写（着色器配对不上就是这个原因） |
| **libnx 的 `svcWaitProcessWideKeyAtomic` / `binderCreate`** | 冻死现场的两个落点，用于读崩溃栈 |
| **NVK 的能力边界** | Switch 上哪些 Vulkan 特性可用（ZCULL、ROV、多视图…），决定能不能省掉某些拷贝 |

## 6. 本仓库里的东西（对照用）

```
patches/nfsmw-nx-sdk.patch   对 nfsmw-nx SDK 的 81 个文件改动（20,879 行）
app/src/nativo/*.cpp|h       2K13 侧原生渲染器实现（28 个文件）
app/CMakeLists.txt           应用工程
app/huecos.toml              codegen 空洞表（函数边界分析结果，不含代码）
app/nba2k13_manifest.toml    codegen 输入清单
tools/                       构建 / 推卡 / 符号化 / 像素比对
```

`app/huecos.toml` 是"哪些地址区间 codegen 没自动认出来"的清单 —— 是分析数据，不是游戏代码。
你自己的函数边界会跟这份不一样，可以当参考，不能直接套用。
