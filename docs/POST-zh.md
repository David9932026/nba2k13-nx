## 正文

大家好。

我做了一个 **《NBA 2K13》Xbox 360 版 → Nintendo Switch 的原生移植**（不是模拟器）：用 ReXGlue 把游戏的
PowerPC 代码静态重编译成 C++，GPU 那边不模拟 Xenos，而是直接读游戏写给显卡的 PM4 命令环，用 Vulkan（NVK）
画同一帧。渲染器是从开源的 NFSMW-NX 那套原生渲染器移植过来的。

**基础移植已经完成，能玩，能打完整场比赛，掌机模式大部分时间 30 帧。** 现在卡在几个具体的渲染问题上，
一个人推不动了，想找有相关经验的人接手收尾。

---

### 项目现状

**已完成、能跑的部分：**

- 平台接入：Switch 原生（devkitAArch64 + libnx），Vulkan 走 NVK，自建着色器库
- 代码层：`default.xex` 静态重编译 59,585 个函数，加上代码生成器漏掉的空洞补扫
- 着色器：7,380 个着色器翻译并打包（这套游戏用的是 2008 版容器 `0x102A1100`，上游几个移植项目都没有，是自己补的）
- 资源：游戏资产解包（16.02 GiB）、着色器容器扫描与配对
- 输入：手柄映射完成，默认索尼布局；**拆 Joy-Con 本地双人可用**
- 画面：主菜单 / 选项 / 训练 / **整场比赛** / 赛前 MV / 回放 / HUD / 记分牌 / 水印，都能正常出
- 音频：XMA 在机器上解码，能出声
- 帧数：掌机模式大部分时间 **30 帧**
- 调试：游戏内可 runtime 开关每一个补丁的面板，真机取证流程（脚本化输入 + 渲染目标导 PNG + 像素统计）

**还缺的、也就是需要接手的部分：**

1. **部分场馆木地板整片发黑**（渲染器问题）
   已经排除：子区域取样、resolve 裁剪、mipmap、读深度的光照步骤、阴影缩放。PC 上也能复现，所以与主机无关。
   特征是木纹没了但三秒区刷漆还在、球场边线到黑块边缘就断 —— 是画地板那一步本身错了。
   下一步：用"跳过指定着色器"的开关二分，配像素统计定位到具体那次绘制。

2. **技术统计页的球员头像碎片**
   选项菜单那处已修好，统计页这处没有。它采样的纹理落在别人的 resolve 内部，而且格式是 resolve 产不出来的
   压缩格式（DXT/DXN 系），等于把 CPU 写的字节当像素读了。需要把这处改成在 CPU 侧正确解码。

3. **赛前 MV 仍有两层画面叠着**
   已经修掉一个原因（兜底逻辑拿场景中间图当画面），日志确认修的在起作用，但重影还在 → 说明还有第二条路径。
   残留接缝的形态像"640×360 的层被放大塞进画面某个象限"。

4. **个别菜单文字被裁**（`THUNDER` 显示成 `UNDER`）
   基本锁定在"声明尺寸小于 resolve 的纹理会被裁剪"这条规则，波及到字体图集。

5. **内存偏紧**：guest 物理堆只有 512 MB，现在靠 resolve 缓存 LRU（上限 96）和一个 16 MB 的对齐保险垫撑着。
   保险垫不能动（试过，游戏越界写踩坏数据）。还有优化空间但需要谨慎。

6. **比赛有段落掉到 ~20 帧**，CPU 100% 与 GPU 99.7% 同时出现，需要性能断面分清主次。

7. **菜单音频轻微卡顿**（线程优先级已调过，剩下要靠测）

> 60 帧做不到：模拟 Xenos 每次绘制 ~80 µs CPU，900 次绘制就是 12 帧天花板。这是量出来的，不是猜的。
> 原生渲染器是 1.5–1.8 µs/绘制，所以这条路才有 30 帧。
