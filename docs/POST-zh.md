## 正文

**《NBA 2K13》Xbox 360 版 → Switch 原生移植，不是模拟器。**

做法：`default.xex` 的 PowerPC 代码用 ReXGlue 静态重编译成 C++，Switch 上编译成原生程序；GPU 那边不模拟 Xenos，
直接读游戏写给显卡的 PM4 命令环，用 Vulkan（NVK）画同一帧。渲染器是从 NFSMW-NX 那套原生渲染器移植过来的。

**现在是能玩的**：能进比赛、能打完整场、掌机模式大部分时间 30 帧、拆开 Joy-Con 能本地双人。

**但没做完。** 剩下的全是渲染器里的活儿 —— 不是搬砖，是那种要盯着一帧一帧对比才能定位的问题，我一个人推不动了。
我把知道的全写下来了，接手不用从零开始。

## 已经做完的部分（有数据支撑的）

**平台与代码层**

- Switch 原生构建：devkitAArch64 + libnx；Vulkan 走 NVK（mesa-switch 编出的 `libvulkan.a`）
- `default.xex`（8,122,368 B，Title ID `545408A2`）重编译出 **59,585 个函数 / 435 个文件**
- 代码生成器漏掉的热点函数补扫（有一个漏掉的入口直接导致第二/第三节崩溃，补上后才稳定）

**着色器**

- **7,380 个着色器**翻译并打包（库文件 259,964,744 B）
- 这套游戏用的是 **2008 版着色器容器**（签名 `0x102A1100`），上游几个移植项目都没有实现：
  头长度 36 字节（不是 24）、微码要从 `virtualSize + physicalOffset` 取、VS 元素表在 `cab+36`
- 最麻烦的是配对：像素着色器能精确哈希命中，但**顶点着色器一个都配不上** —— D3D 会改写 fetch 常量
  （有个字从 `0x00000688` 变成 `0x402034C1`）。最后靠"所有差异都落在容器声明的那条 fetch 指令三个字里"
  这条位置规则配上
- 中间踩过一个硬限制：着色器寄存器超过 **256** 直接 `DEVICE_LOST`，为此全量重编过一轮

**画面与系统**

- 44 个已验证的修复，每个都有明确的症状和判据。挑几个代表性的：
  - 阴影边缘闪烁：解析过的纹理没有报告自己的 `1/尺寸`，PCF 采样点全落到同一个 texel
  - 内存缓慢泄漏：resolve 缓存只增不减，加了 LRU，上限 96
  - 整机冻死：guest 物理堆 512 MB 耗尽 → 日志洪水 + nv IPC 风暴 → 全线程卡在 `binderCreate+0x18`，
    现在有 60 秒一次的内存账本
  - CPU 100% 却不走帧：不是算力不够，是 futex 在忙等，改成定点唤醒
  - 头像框里"背后站着上一个人"：清除方框只清了深度没清颜色
  - 比赛里记分牌和水印消失：呈现时把"被下游采样"的中间图当成了画面
- 游戏内调试面板：**L3 + R3 + 十字键右**，每个补丁都能运行时开关，改一个参数不用重新编译就能看效果
  （游戏里 `L+R+十字键` 是战术键，所以避开了）

## 剩下的问题（这才是要找人的原因）

### 1. 部分场馆木地板整片发黑 🔴 未定位

**现象**：某些场馆里木地板不是木纹，是一大块不规则的纯黑。但**三秒区刷的漆还在**，球场边线画到黑块边缘
就断掉。边线断掉这点很关键 —— 说明不是"上面盖了东西"，是**画地板那一步本身错了**。

**已经排除的**（都在 PC 上做 A/B，统计"近黑像素占比"，不看图）：

| 关掉什么 | 结果 |
|---|---|
| 纹理落在 resolve 内时的子区域取样 | 黑地板照旧 |
| "声明尺寸小于 resolve 就裁剪"（只取左上角） | 照旧 |
| mipmap | 照旧，而且**更糟**（带大片黑的帧 10 → 25） |
| 唯一读整场深度图的那步光照（`n982`） | 照旧 |
| 阴影图缩放（Switch 上设的 70%） | 70 / 100 各跑一轮，**无差别** |

**现有证据**：

- **PC 上也复现**（活塞 vs 勇士，甲骨文球馆），所以跟主机无关，是渲染器本身
- `n982` 在 Switch 日志里 79 次都只采样 `05822000`（1280×720 深度）—— 它**不是地板**，别去那找
- 部分场馆纹理是从 1024×1024 的 resolve 里取样的（`0F5D0000`、`0FB21000`、`10072000`、`105AD000`），
  其中含 **DXT1 / DXT5 / DXN 压缩格式**和 formato 59 —— **resolve 永远产不出这些格式**

**下一步怎么打**（写清楚了，照着做就行）：

1. 用 `nba2k13_nativo_diag_omitir_ps` 按着色器指纹二分跳过，每次跑一场演示
2. 用脚本统计"黑像素占比 ≥15% 的帧数"来判定效果 —— **不要用眼睛，也不要让视觉模型判**
3. 跳过哪个之后木地板整片消失 = 找到画地板的那次绘制
4. 然后看它采样的纹理：基地址、声明格式、是否落在某张 resolve 内
5. 候选修法：**压缩格式 / 非 8888 的 texture fetch 落在 resolve 内时，把这块判给 CPU，
   从 guest 内存按它自己的格式解码**，而不是按 resolve 的格式去读

> 注意：演示模式每次随机球队和场馆，两轮之间逐像素差异 50–80%，**逐帧对比是无效的**，
> 必须跨整段聚合统计。

### 2. 技术统计页的球员头像碎片 🔴 未解

**现象**：头像框被别的东西占满 —— 队徽碎片、竖条纹、灰白黑糊块，或者别的球员的片段。
（选项菜单里的同类问题已经修好，真机确认；统计页这处不一样。）

**已经排除的**：

| 试过 | 结果 |
|---|---|
| 别名身份刷新（假设旧身份没更新） | 真机日志 **0 次触发**，画面无变化 |
| CPU 重写 resolve 内存检测（记录指纹逐帧比对） | 触发 3 次（`0FB21000 1024×1024` 等），画面**无变化** |
| 直接 dump 内存原始字节（按下 8888 + 128/256 方图匹配） | **抓到 0 个文件**，格式和区间猜错了 |

**现有证据**：

- 日志里大量 `C23 dentro`：256×256 的纹理落在 `0FB21000 1024×1024` 这张 resolve 内部，
  判定为"装不下，改从 guest 内存读"或"从 resolve 里子采样"
- `C13 cuadro lleno opaco sin textura: PS F0412447847F6D27 en 1040x1040` —— 那头像目标上有
  "全屏不透明但没贴纹理"的绘制
- **赛前首发卡那 10 张 150×300 不是统计页头像**：PC 上导出看是干净的，说明那条路径没问题，
  统计页走的是另一条

**最像的解释（假设，未验证）**：统计页头像采样的是一块**压缩格式**的纹理（DXT/DXN 系），落地位置
在别人的 resolve 里；resolve 产不出压缩格式，于是渲染器把 CPU 刚写进去的字节当像素读 → 碎片看起来像别的东西。

**下一步**：给"格式不同 → 从 guest 内存读"这条分支加限速日志（格式、基地址、落点、读出前 16 字节），
真机进一次统计页让日志说实话；然后按真实格式在 CPU 侧解码。判据是导出 PNG 的非零像素占比和边缘梯度。

### 3. 赛前 MV 仍然两层画面 🟠 修了一半

**现象**：赛前预热 MV 播的时候，画面里同时有两个会动的东西，一个清楚一个虚。

**已经做的**：兜底逻辑（某些时刻 Swap 没像素就"拿整帧拷贝当画面"）会把**场景中间图**当画面呈现，
而游戏自己在往真正的 Swap 上画，两者交替 → 看着就是两层。现在改成兜底前先看这一发送里 Swap 有没有绘制，
有就呈现 Swap 自己。PC 上接缝帧从 **10 张降到 2 张**。

**但真机上两层还在。** 日志侧每 10 秒都在打"呈现 Swap 自己"（数百次），兜底只剩 1 次 ——
所以**还有第二条路径**在产生两个画面，不是选错缓冲。

**线索**：剩下那 2 张接缝帧都在换场过程里，兜底没触发、修复也没触发。残留接缝的形态是
"某个象限变成一块模糊/去饱和的矩形" —— 典型的**半分辨率层（640×360）被整屏放大后只占 1/4**，
也就是 UV 或裁剪算错。

**下一步**：需要一张真机照片，确认模糊那层占画面哪一块（左上 1/4 / 整屏 / 下半）；
然后去查 `18C3D000`、`1A353000` 这两张 640×360 和 640×720 那一档 pitch 的裁剪窗口与 UV 来源。
判据：接缝检测脚本的"带接缝帧数"归零。

### 4. 个别菜单文字被裁 🟡 方向明确

`THUNDER` 显示成 `UNDER`，字被切掉一截。文本走图集，取样矩形越界就被裁。
嫌疑在"声明尺寸小于 resolve 的纹理会被裁剪"这条规则 —— 如果是字体图集正好落在某张 resolve 里就会被波及。
**下一步**：打开 `C18 tamano` 日志，找声明尺寸与字体图集匹配的那条，看裁剪矩形是否越界。

### 5. 内存偏紧 🟡 有空间但风险高

guest 物理堆只有 **512 MB**，开机常驻就占掉 465 MB。现在靠两样撑着：
resolve 缓存 LRU（上限 96）、以及一笔 64MB 对齐申请带的 16 MB 保险垫。

**保险垫不能动。** 我试过为了省这 16 MB 把它撤掉，结果游戏越界写踩坏相邻块，
赛前 MV 每次都在着色器加载（`PM4_IM_LOAD`）那一步卡死。定位靠的是拿"上一个正常包的日志"做差异比对，
两行 `[PHYSPAD]` 就一眼看出来了。真要优化，得先从别处省。

### 6. 比赛有段落掉到 ~20 帧 🟡 需要性能断面

CPU 100% 和 GPU 99.7% 同时出现，要看 fences 等待时间才能分清谁是真瓶颈。
（历史教训：之前有一次"掉帧"其实是探针导致的 —— 导出 PNG 每秒几十次全管线同步，关掉就恢复 30。）

### 7. 菜单音频轻微卡顿 🟡 需要测量

混音线程优先级已经提到 44，XMA 基线是每 10 秒 24,037 次 kick、最大 1.46 ms。剩下要靠抓卡顿时刻的间隔分布。

> **60 帧做不到**，这是量出来的：模拟 Xenos 每次绘制约 80 µs CPU，900 次绘制就是 72 ms 一帧，天花板 12 帧。
> 原生渲染器是 1.5–1.8 µs/绘制，所以这条路才有 30 帧。别再往 60 上花时间。
