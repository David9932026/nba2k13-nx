# 03 · 修复账本（C1 – C49）

每个补丁按同一套格式记：**现象 → 根因 → 做法 → 状态 → 判据**。
状态只有四种：`真机确认` / `PC 验证` / `未验证` / `已回退`。

`已回退` 的那些不是删掉就完事 —— 留着是因为它们说明了哪些路走不通，以及为什么会走错。

---

## A. 骨架与基础（C1 – C14）

| 编号 | 现象 | 根因 / 做法 | 状态 |
|---|---|---|---|
| **C1** | 原生路径要能起得来 | `SistemaGraficoNativo` 接管图形系统，用 SDK 自带 present 而不是 Xenos 模拟 | 真机确认 |
| **C2** | 需要知道每帧到底画了什么 | pass 变体建立 + `caras resueltas` 每秒统计（每张图：副本数、有绘制的份数、被读次数） | 工具 |
| **C3** | 阴影边缘闪 | 解析过的纹理要报自己的 `1/尺寸`，否则 shader 拿到的 0 会让 PCF 采样点全落到同一个 texel | 真机确认 |
| **C5a** | `biblioteca de shaders no disponible` | 着色器库包缺失/格式不符（后来靠 §5 的 2008 容器解析解决） | 已解决 |
| **C5g** | 某些时刻 Swap 没像素，画面不出 | 兜底：拿"整帧拷贝"的图当画面呈现。**这个兜底后来成了预热 MV 双画面的根源，见 C48** | 真机确认（兜底生效）|
| **C6** | 绘制到底进了管线没有 | 每秒打印 `dibujados / rechazados / pipelines / texturas` | 工具 |
| **C7/C8** | 1280×1280 / 格式 37 的方形目标 | 统计方框 pase 数与绘制数；`omitir_cuadrado` 可整体跳过（排查用） | 工具 |
| **C10** | 有绘制被静默丢掉 | PS 不在库里或没翻译时计数并告警，不再无声丢弃 | 工具 |
| **C11** | 真机上分不清跑的是哪个包 | 启动打一行 `C11 BANNER build <时间>` —— **每次真机排查的第一件事就是看这行** | 工具 |
| **C12** | 每个 pitch 的负载分布 | 按 pitch 分桶统计 pass 数、绘制数、Mtexels | 工具 |
| **C13** | 全屏不透明方块却没贴纹理 | 打印 PS 指纹 + 目标尺寸 + z + 掩码，用来定位"某块画面为什么是纯色" | 工具 |
| **C14** | 想知道谁在采样头像纹理 | 每个 pass 打印 PS 指纹、sampler 数、目标尺寸 | 工具 |

## B. 纹理身份与裁剪（C18 – C31）

| 编号 | 现象 | 根因 / 做法 | 状态 |
|---|---|---|---|
| **C18** | 某帧左上角闪出球场，然后黑屏 | fetch 声明的尺寸比实际 resolve 小；整图按 0..1 采样会把画面压进左上角。做法：按声明尺寸把左上角那块拷出来单独用 | 真机确认 |
| **C19** | 法线贴图被当无符号读，光照发平 | fetch 里有符号/伽马组合位（X/Y/Z/W 各 2 bit），按组合记录并正确解释 | 真机确认 |
| **C23** | 纹理落在别人的 resolve 里 | 判断纹理是否"整块落在某个 resolve 内"：能装下就子采样，格式不符或装不下就改从 guest 内存读 | 真机确认 |
| **C24–C26** | YUV 视频/伽马/围栏/微码 | `destinos_srgb`（写入时编伽马）、`yuv_canales = 1`、围栏与微码校验 | 真机确认 |
| **C28/C29** | 选队界面队徽绘制错 | `nba2k13_nativo_alias_color`：同内存不同身份时按颜色重绑定；之后 `rechazados = 0` | 真机确认 |
| **C30** | 头像框里叠着别人的碎片 | **520 pitch 的清除方框只清了深度，没清颜色**。在 `pase` 里按 pitch 记录清除，1040 目标开 pase 前补清 | 真机确认（部分）|
| **C31** | 地板劈成两半、缺瓦片 | 深度 resolve 是分瓦片拼的，拼图时漏了瓦片。`CopiarProfundidad` 按瓦片 join | 真机确认 |

> **C30 的后半截是 C45 才补完的**：C30 只处理了深度，颜色那一半漏了，所以头像背后一直站着上一个人。

## C. 定型案件（C32 – C37）

| 编号 | 现象 | 根因 / 做法 | 状态 |
|---|---|---|---|
| **C32** | 联网初始化卡住 | `inet_addr` 缓存问题（`xam_net.cpp:611`） | 真机确认 |
| **C34** | 上一场比赛的残留进了下一场 | 内容代际 `generacion_contenido` 没随场景切换递增 | 真机确认 |
| **C34b** | 换场后头像/场景错位 | `sembrado_` 配对（成对记录播种与消费） | 真机确认 |
| **C35** | 某层泛光输出空图 | `0F5CE000` 的 fetch 声明与实际格式不符；用 `TexturaResueltaTam(formato_guest)` 兜 | PC 验证（真机未确认）|
| **C36** | CPU 100%、帧不走 | **futex 忙等**：等待线程在自旋而不是被唤醒。改成定点唤醒（`threading_posix.cpp` 的 `RegistroEspera`） | 真机确认（稳定 95–96 帧计数）|
| **C37** | 内存缓慢泄漏直到崩 | `resueltas_` 只增不减。加 LRU，上限 96 | 真机确认 |

**C36 是第二轮最重要的一个**：之前所有"性能问题"的归因都不对 —— CPU 不是算力被榨干，是在自旋。

## D. 冻死治理（C39 – C44）

| 编号 | 现象 | 根因 / 做法 | 状态 |
|---|---|---|---|
| **C39** | 玩一段就整机卡死 | guest 物理堆 512 MB 耗尽 → `Heap exhausted!` @ `xmemory.cpp:1675` → SD 日志洪水 + nv IPC 风暴 → 全线程卡在 `binderCreate+0x18`。做法：日志限速 + 每 60 秒打内存账本 | 真机确认 |
| **C39b** | 不知道谁在吃内存 | 逐出 bases 日志 | 工具 |
| **C40** | 随机崩在 `pthread_setcanceltype` assert | 按 POSIX 语义补齐 | 真机确认 |
| **C41a** | 导出深度图全黑 | `EscribirPngDeImagen` 用 COLOR aspect 去拷 DEPTH 图 = 无效拷贝。改成 DEPTH aspect + D32/D24 自动识别 + 转灰度 | PC 验证 |
| **C41b** | 想省 16 MB | 把 64 MB 对齐申请的保险垫撤了（`rex_fisico_sin_relleno_64mb`）。**这是本项目的头号自伤**，见下 | **已回退** |
| **C42** | 选项菜单头像碎片 | 假设 fetch 声明的旧身份没刷新，加 `RefrescarAliasMismaMemoria` | **已证伪**（真机 0 触发，代码保留无害）|
| **C43** | 预热 MV 放 5 秒画面定格 | PM4 环死锁：`while (lector.Pendientes())` 里 `leido` 永不前进，环原地空转 33 万圈/秒。加看门狗：连续 64 步 `pos == leido` 判停滞并打印 | 真机触发（作为诊断）|
| **C44** | 想让 C43 自愈 | 停滞超 5 秒丢弃卡包、`pos` 重对齐 WPTR | **已关闭** —— 丢掉的是对齐正常的半截包，会让后续数据错位 |

### C41b 案件全过程（务必读）

`[PHYSPAD]` 两行日志的差别就是全部真相：

```
好：  [PHYSPAD] 64MB-aligned request widened to 0xc00000 B so the neighbouring block cannot be overrun
坏：  [PHYSPAD] C41b relleno desactivado: 4194304 B se queda con su tamano (alineacion 0x4000000)
```

撤掉保险垫 → 游戏越界写踩坏相邻块 → 卡在 `op=C0012700`（低字节 `0x27` = `PM4_IM_LOAD`，着色器加载）→ 画面定格。

把它关回去之后，预热 MV 立刻正常、比赛能进。

**教训：新包出现退化时，先拿"上一个正常包"的日志做差异比对，不要急着加新补丁。**
这条教训当时是靠用户一句话点醒的："找回之前运行正常的日志回看一下，你肯定是删掉了一些东西。"

## E. 画面元素修复（C45 – C48）

| 编号 | 现象 | 根因 | 做法 | 状态 |
|---|---|---|---|---|
| **C45** | 头像框里"背后站着杜兰特" | 520 pitch 的清除方框只清深度（C30 的一半），1040 头像目标的 EDRAM 颜色基底 `000` 保留着上一次画的人 | 同基底的 1040 目标开 pase 前先清色（loadOp=CLEAR），cvar `nba2k13_nativo_alias_color_cuadro` | **真机确认** |
| **C46** | 比赛里记分牌 + 2K13 水印消失 | `presenta_cinematica` 选目标时只判"整帧拷贝且 Swap 没像素"，比赛里的 `0548A000` 也满足 —— 但它是**被下游采样的中间图** | 90 帧内被采样过的宽图（≥1150 px）跳过，不拿去当画面 | **真机确认** |
| **C47** | 技术统计页头像碎片 | CPU 重写了 resolve 的 guest 内存，却还从 GPU 副本采样 | 记录 64 个指纹样本，每帧比对，变了就改从 guest 内存读，cvar `nba2k13_nativo_resueltas_pisadas` | **未验证**（真机触发 3 次，但不是统计页头像的成因）|
| **C48** | 预热 MV 两个画面（一个虚一个实） | C5g 兜底把场景中间图（`0B05A000`/`0B24A000`）当 Swap 呈现，而那些时刻游戏自己在往 `035F0000`/`03988000` 画 → 两者交替，看着像两层 | 兜底前先看 Swap 这一发送里有没有绘制，有就呈现 Swap 自己，cvar `nba2k13_nativo_c5g_respeta_swap_dibujado` | PC 验证（接缝帧 10 → 2）；**真机仍有两层，未解决** |
| **C49** | 想直接看统计页头像在内存里的原始字节 | —— | 按格式 8888 + 128/256 方图 dump guest 原始数据（最多 24 个文件） | **探针打空**（设的格式/区间不对，0 个文件）|

### C45 的判据（这条值得照抄）

PC 上把 1024 目标导出成 PNG，逐像素比对修前/修后：

| | 非零像素 | 结论 |
|---|---|---|
| 修前 `resuelta10071_03` | 182,234 | 一前一后两个人 |
| 修后 勒布朗那张 | 148,662 | 只有一个人 |
| 修后 杜兰特那张 | 135,774 | 只有一个人 |
| `修前 − 勒布朗` | 44,352 px | 就是"多出来的那个人" |
| `修前 ∩ 杜兰特` | 114,800 px | 确认重叠的是杜兰特 |

**这类结论必须落在像素数上，不能落在"看着像没问题"上。**

## G. 探针与工具（不是修复，但没有它们什么都修不了）

| 名字 | 用途 |
|---|---|
| `[CUADRADOR]` | 每个 1280×1280 方框：颜色信息、控件、此前绘制数、是否清除 |
| `[MUESTRA]` | 某个基地址被谁采样、声明尺寸、是否命中 resolve |
| `C2 caras resueltas` | 每秒每张图的副本数、被采样的次数（能看出"这张图没人读"）|
| `[FRAMESIG]` / `[SEQDUMP]` | 每帧绘制签名，用来判断两次运行是不是同一帧 |
| `descartes` | 环里每个 DRAW 都落到"画了/后端拒绝/可见性剔除"之一，一个不漏 |
| `[PHYSPAD]` | 64 MB 对齐申请与保险垫状态 |
| `[C39] monton fisico` | 每 60 秒物理堆账本 |
| `nba2k13_nativo_diag_fetch_ps` | 给定 PS 指纹，每秒打印它所有 sampler 的完整 fetch 常量 |
| `nba2k13_nativo_diag_omitir_ps` | 跳过指定 PS 的绘制（**二分定位"这块画面是谁画的"最快的手段**）|
| `volcar_destino_ancho` / `volcar_resuelta_ancho` | 把指定宽度的渲染目标/解析图导出成 PNG（排查用，**别开着玩** —— 每秒几十次全管线同步，帧数直接崩）|
